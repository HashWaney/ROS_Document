
智能指针本质上就是: 用RAII的方式管理堆内存对象, 也就是说, 智能指针不是高级指针语法, 而是C++用来表达对象归谁管, 什么时候释放, 能不能共享的工程工具.


### 核心结论

C++里最重要的问题之一是:
```
这个对象到底归谁所有?
```
智能指针就是用来回答这个问题的.
三个结论:
```
std::unique_ptr<T> // 独占这个对象,负责释放
std::shared_ptr<T> // 多个人共享这个对象,最后一个负责释放
std::weak_ptr<T> // 只观察这个对象,不负责延长它的生命周期
```
现代C++的基本原则是:
```
能用unique_ptr, 就不要用shared_ptr;
能用引用或裸指针表达: 只使用不拥有,就不要乱用shared_ptr;
shared_ptr 要谨慎使用;
weak_ptr 用来打破shared_ptr循环引用.
```

### What: 智能指针是什么?

### 普通指针是什么?

```
Robot* robot = new Robot();
```
这里的robot里面存的是一个地址, 这个地址指向堆上的Robot对象.但是普通指针有一个问题:
```
它只表示“我知道这个对象在哪里”,但不表示“我是否负责释放它”
```
例如:
```
Robot* robot = new Robot();
robot->start();
delete robot; // 释放
```
需要手动delete. 如果忘记,就会内存泄漏. 如果重复释放,可能会导致崩溃, 如果释放后继续使用, 也可能导致崩溃.
### 智能指针是什么?

智能指针是一个对象, 不是普通裸指针. 它内部保存一个裸指针,并在合适的时候自动释放.
```
#include<memory>
std::unique_ptr<Robot> robot = std::make_unique<Robot>();
robot->start();
```
不需要再写:
```
delete robot;
```
因为unique_ptr析构时会自动释放它管理的对象.

## Why: 为什么C++需要智能指针

### 堆对象生命周期不自动结束

先看一个例子:
```
void run(){
	Robot robot;
	robot.start();
}
```
这里robot是栈对象. 函数结束时, robot自动析构.
但是如果写成:
```
void run(){
	Robot* robot = new Robot();
	robot->start();
}
```
这个对象在堆上. 函数结束后, robot这个局部变量消失了, 但堆上的Robot对象不会自动释放.也就是说
```
栈对象生命周期由作用域自动管理
堆对象生命周期必须要有人负责管理.
```
普通裸指针没有所有权语义, 所以问题来了:
```
谁负责delete?
什么时候delete?
能不能复制这个指针?
复制后谁delete?
多个模块都拿着这个指针怎么办?
```
智能指针就是为了解决这些问题的.

### 普通裸指针表达不清“所有权”

看这个函数:
```
void setController(Controller* controller);
```
你看到这个参数, 会有几个疑问:
```
这个函数会不会保存Controller?
这个函数会不会delete Controller?
controller 可不可以为空?
调用方还拥有它?
```
裸指针表达不清楚这些问题.如果改成:
```
void setController(std::unique_ptr<Controller> controller);
```
含义就很明确:
```
调用方把Controller的所有权交给setController, setController之后, 调用方不再拥有它
```
