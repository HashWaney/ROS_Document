在学习ROS2的Action工程时候, 发现在原有工程目录结构上接入自定义interface目录的时候. 在编写CMakeList.txt文件的时候, 忘记新建ros_patrol_bt_action_node.cpp源文件, 可执行文件和该源文件名称一致, 但是引入的源文件名称为ros_patrol_bt_node.cpp源文件, 导致在编译过程中发生一系列文件.另外还有在ament_target_dependencies中未依赖behaviortree_cpp导致在编译的时候缺少相关的依赖源文件. 特此做下记录.

### 问题的最终结论
核心问题不是ROS2 Action本身, 也不是bt_patrol_interfaces本身, 而是bt_patrol_demo的CMake配置写错了. 
主要有两个确定错误:

#### 1、 ros_patrol_bt_action_node用错了源码文件

原来写的是:

```
add_executable(ros_patrol_bt_action_node 
	src/ros_patrol_bt_node.cpp
)
```

这导致CMake实际上用的旧的低电量demo文件去生成新的Action节点.
所以日志中出现了:

```
CMakeFiles/ros_patrol_bt_action_node.dir/src/ros_patrol_bt_node.cpp.o
```

正确应该是:

```
add_executable(ros_patrol_bt_action_node 
	src/ros_patrol_bt_action_node.cpp
)
```

#### 2、 ros_patrol_bt_action_node少链接了behaviortree_cpp

原来写的是:

```
ament_target_dependencies(ros_patrol_bt_action_node
	rclcpp
	rclcpp_action
	std_msgs
	bt_patrol_interfaces
)
```

少了:

```
behaviortree_cpp
```

所以链接阶段报错:

```
undefined reference to `BT::BehaviorTreeFactory`
undefined reference to `BT::Tree::tickOnce`
undefined reference to `BT::StatefulActionNode`
```

正确是的应该是:

```
ament_target_dependencies(ros_patrol_bt_action_node
	rclcpp
	rclcpp_action
	std_msgs
	behaviortree_cpp
	bt_patrol_interfaces
)
```

### 最终正确的CMake关键片段

以后可以把这段作为模版记住:

```
#BT+ROS2 Action Client
add_executable(ros_patrol_bt_action_node
	src/ros_patrol_bt_action_node.cpp
)

ament_target_dependencies(ros_patrol_bt_action_node
	rclcpp
	rclcpp_action
	std_msgs
	behaviortree_cpp
	bt_patrol_interfaces
)
```

这里要区分两件事:

```
add_executable(....)
```
表示这个可执行程序由哪些.cpp文件生成

```
ament_target_dependencies(....)
```

表示这个可执行程序需要链接哪些ROS2包 /第三方库


### 这次排查过程中暴露出的几个经验点

#### 经验1: collect2 : error : ld returned 1 exit status 不是根因

贴出来的:
```
collect2 : error : ld returned 1 exit status 
```
只是连接器最后的总结. 真正有用的是它最前面的:
```
undefined reference to ...
cannot find ....
```
所以以后看到链接失败, 不要只看最后几行, 要用:
```
grep -n -B3 -A10 "undefined reference\|cannot find\|ld returned" /tmp/bt_build.log
```
这次真正关键的日志是:
```
undefined reference to `BT::BehaviorTreeFactory::BehaviorTreeFactory()`
undefined reference to `BT::BehaviorTreeFactory::createTreeFromFile(...)`
undefined reference to `BT::Tree::tickOnce()`
undefined reference to `BT::Tree::sleep(...)`
```
这就直接说明:
```
BehaviorTree.CPP 的头文件编译通过了, 但是库没有链接进来
```

#### 经验2: 编译通过不代表链接通过

C++工程有两个阶段:
```
编译阶段: 检查头文件,语法,类型
链接阶段: 检查函数实现所在的库有没有真正连上
```

这次就是典型的
```
#include "behaviortree_cpp/bt_factory.h" 能找到
所以编译通过

但是behaviortree_cpp 没有链接
所以链接失败
```
判断方式:
```
fatal error: xxx.hpp: No such file or directory
			-> 编译阶段,头文件找不到
undefined refernece to xx
	 -> 链接阶段,库没链接或链接错了
```

#### 经验3: CMake目标名和源码文件必须对应

日志里有一个非常关键的线索:
```
CMakeFiles/ros_patrol_bt_action_node.dir/src/ros_patrol_bt_node.cpp.o
```

这句话说明:

```
ros_patrol_bt_action_node 这个 target 实际编译的是 ros_patrol_bt_node.cpp
```
这和我们预期不一致,所以就能马上定位到:
```
add_executable(ros_patrol_bt_action_node 
	src/ros_patrol_bt_node.cpp
)
```
写错了, 以后看到:
```
CMakeFiles/某个target.dir/src/某个cpp.o
```
要习惯性检查:
```
这个 target 是否用了正确的源码文件?
```

#### 经验4: ROS2里优先用ament_target_dependencies
之前尝试:
```
target_link_libraries(ros_patrol_bt_action_node
	BT::behaviortree_cpp
)
```
但是当前Jazzy环境里报过:
```
BT::behaviortree_cpp target was not found 
```
所以在ROS2 ament工程里, 当前更稳的是:
```
ament_target_dependencies(ros_partol_bt_action_node
	behaviortree_cpp
)
```
也就是说: ROS2 包依赖, 优先放进ament_target_dependencies(), 不要一开始就强依赖某个imported target名称, 除非确认这个包确实导出了那个target.

#### 经验5: workspace路径必须统一

你真实的workspace是:

```
/home/hash/Desktop/ros2_btree/ros2_bt_ws
```
但是中间有命令用了:
```
~/ros2_bt_ws
```
这实际指向
```
/home/hash/ros2_bt_ws
```
所以遇到过:
```
find: '/home/hash/ros2_bt_ws/install/bt_patrol_interfaces': No such file or directory
```
这不是接口包没生成, 而是路径查错了.

#### 经验6: install/setup.bash报local_setup不存在,通常是install残留坏了
遇到:
```
not found: ".../install/bt_patrol_demo/share/bt_patrol_demo/local_setup.bash"
```
通常说明:
```
install/setup.bash里记录了某个包
但是这个包没有完整安装成功
或者install 目录残留了旧状态
```
解决方式不是继续source, 而是清理:
```
cat /home/hash/Desktop/ros2_btree/ros2_bt_ws
rm -rf build install log
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-up-to bt_patrol_demo
source install/setup.bash
```
