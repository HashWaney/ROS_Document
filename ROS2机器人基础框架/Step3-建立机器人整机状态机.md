### 一、先明确FSM的职责

建立一个独立的`robot_system_manager` 节点, 作为机器人整机状态的统一管理者.
它主要解决三个问题:
- 1、机器人当前处于什么运行状态?
- 2、收到启动、停止、故障、急停等事件时, 是否允许状态切换?
- 3、切换状态时, 需要通知哪些模块执行相应操作?

需要注意到, 整机FSM不等同于ROS 2 Lifecycle.

| 系统              | 负责管理               |
| --------------- | ------------------ |
| 整机FSM           | 机器人运行模式, 状态转换和运行许可 |
| ROS 2 Lifecycle | 单个节点的配置、激活、停用和清理   |
| Behavior Tree   | 自动任务的执行顺序、条件判断和恢复  |
| Fault Manager   | 故障检测、分级、锁存及清除条件    |
| Motion Manager  | 运动指令仲裁、超时停机和安全执行   |
ROS 2 Lifecycle 已经具有`Unconfigured` 、`Inactive`、`Active` 和 `Finalized` 等标准节点状态, 不应该重新实现这些机制

### 二、定义六个整机状态
建议先采用六状态模型, 避免开始引入太多业务相关状态

| 状态     | 含义          | 是否允许运动 |
| ------ | ----------- | ------ |
| INIT   | 系统启动、初始化及自检 | 否      |
| IDLE   | 初始化完成、等待任务  | 否      |
| MANUAL | 手动控制模式      | 条件允许   |
| AUTO   | 自动任务执行模式    | 条件允许   |
| FAULT  | 存在阻止运行的故障   | 否      |
| ESTOP  | 紧急停止状态      | 否      |

其中`MANUAL` 和 `AUTO` 只代表允许使用对应的运动控制模式, 不代表一进入状态就自动移动, 另外, 网络断开, 电量低, 传感器故障等不直接设计为独立的整机状态. 这些信息由各自模块管理, 再根据严重程度决定是否触发整机状态转换.

### 三、状态转换设计
![[Pasted image 20261117172816.png]]


**关键转换规则**

| 当前状态   | 事件                 | 目标状态   | 前置条件               |
| ------ | ------------------ | ------ | ------------------ |
| INIT   | INIT_SUCCESS       | IDLE   | 必要模块自检完成           |
| INIT   | INIT_FAILED        | FAULT  | 初始化失败              |
| IDLE   | START_MANUAL       | MANUAL | 运动控制模块就绪,无阻断故障     |
| IDLE   | START_AUTO         | AUTO   | 自动任务依赖满足, 无阻断故障    |
| MANUAL | STOP               | IDLE   | 撤销运动许可             |
| AUTO   | STOP/TASK_FINISHED | IDLE   | 取消或结束自动任务          |
| 任意运行状态 | FAULT_RAISED       | FAULT  | 出现阻断允许的故障          |
| 任意状态   | RESET_TRIGGERED    | ESTOP  | 紧急停止触发             |
| FAULT  | RESET_FAULT        | INIT   | 故障源已消除且明确请求复位      |
| ESTOP  | RESET_ESTOP        | INIT   | 急停源解除, 安全条件满足、人工复位 |
其中有几条必须坚持的设计约束:
**第一: 手动模式与自动模型不允许直接互相切换**

> 必须先退出当前运动模式, 撤销原控制源许可并进入IDLE, 再进入另一种模式, 避免两个控制源争夺底盘.

**第二: 急停优先级最高**

> 当 ESTOP 与普通故障同时发生时, 优先保持急停状态. 急停解除后也不能直接恢复此前的AUTO或MANUAL. 软件状态机不是硬件安全急停的替代品. 
> 真正的硬件急停及驱动器安全停机需要独立机制保障

**第三: 故障不能简单地自动清除**

> 故障原因消失后, 仍需要根据故障等级与复位策略决定是否恢复. V1对阻断故障采用显示复位策略

**第四: 状态机不能作为唯一的运动安全机制**

> 运动节点还必须具备独立的指令超时保护、速度限制和停止策略. 网络通信中断时, 尤其不能依靠状态机的消息一定及时到达来保证停车
